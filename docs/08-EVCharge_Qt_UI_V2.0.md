# EVCharge Qt UI 总设计 V2.0

Qt 用户端 + Qt 管理端 UI

## 1. 设计说明

设计依据：仓库 README.md、docs/00-SRS-V1.0.md、docs/03-API.md，以及老师原项目要求书。老师要求书用于确定必做功能，仓库最新版需求确定具体业务范围。

覆盖当前仓库中与 Qt 用户端、Qt 管理端 UI 直接相关的主要需求。Socket、业务规则、SQLite、多线程、Web、ML 等由对应模块实现。

当前 `develop` 架构中，`qt-server` 与 `qt-admin` 已拆分：

```text
qt-user
   ↓ TCP
qt-server
   ↑ TCP
qt-admin
```

- `qt-server` 独立负责 `QTcpServer`、业务逻辑和 SQLite；
- `qt-admin` 是独立 Qt 客户端；
- `qt-admin` 不直接访问数据库，也不承担服务端职责。

Qt 页面统一遵循以下调用链，不允许页面自行创建或直接维护 `QTcpSocket`：

```text
UI Page
   ↓
Controller / ViewModel
   ↓
SocketClient
   ↓
qt-server
```

## 2. 统一页面状态规范

所有用户端和管理端页面统一考虑以下页面状态，具体样式由 QSS 统一实现：

| 状态 | 页面表现 | 统一规则 |
| --- | --- | --- |
| Loading | 加载提示 / Loading 占位 | 正在请求数据时显示，避免页面无反馈 |
| Empty | 空状态提示 | 列表、表格无数据时显示 Empty State，不显示空白区域 |
| Error | 错误提示 | 展示服务端 `code/message` 或本地错误信息 |
| Timeout | 超时提示 + 重试 | 请求超时后允许用户主动重试 |
| Socket Disconnected | 断线提示 | Socket 断开后禁止继续提交写操作，待重连后恢复 |
| Disabled | 控件禁用态 | 当前状态不允许执行的按钮必须 Disabled |
| Submitting | 提交中 | 写操作提交后按钮进入提交中状态，防止重复提交 |

补充统一规则：

- Session 失效后清理本地会话并返回对应登录页；
- Socket 断开时，充值、创建订单、开始/停止充电、结算、冻结/解冻、远程重启、新增站点等写操作均不可继续提交；
- 请求失败或超时时，页面保留当前有效数据，并提供明确提示；
- 状态恢复后重新拉取权威数据，不由 UI 自行修正业务状态。

## 4. Qt 用户端 UI 总设计

用户端采用模拟手机端布局。主导航保留：首页 / 充电 / 我的。

导航关系统一为：

```text
U02
├─ 查看详情 → U03
└─ 导航     → U06

U03
└─ 导航     → U06
```

| 编号 | 页面 | 主要目的 | 关键跳转 |
| --- | --- | --- | --- |
| U01 | 手机号登录 | 手机号免密登录；不存在则自动注册 | 登录成功 → U02；冻结且有活动订单 → U04 |
| U02 | 首页 / 附近充电站 | 定位、展示附近站点与推荐 | 查看详情 → U03；导航 → U06；充电 → U04；我的 → U05 |
| U03 | 充电站详情 | 查看站内电桩并选择可用桩 | 导航 → U06；选择电桩 → U04 |
| U04 | 当前充电 / 订单处理 | 覆盖预约、开始、充电、停止、结算 | 完成后 → U02 / U05 |
| U05 | 我的 | 用户资料、钱包、历史订单 | 首页 → U02；未完成订单 → U04 |
| U06 | 地图导航 | 腾讯地图路线规划 | 返回 → 来源页（U02 / U03） |

### U01 手机号登录页

| 区域 | 元素 | 作用 | 数据来源 |
| --- | --- | --- | --- |
| 品牌区 | Logo / “充电用户端”标题 | 识别系统 | 本地静态资源 |
| 登录区 | 手机号输入框 | 输入 11 位手机号 | 用户输入 phone |
| 登录区 | 登录按钮 | 发起登录/自动注册 | USER_LOGIN |
| 提示区 | 格式或状态提示 | 显示登录失败、冻结等原因 | 本地校验或服务端 code/message |
| 冻结处理 | 活动订单判断结果 | 冻结且存在活动订单时仅允许进入 U04 完成收尾 | 服务端用户状态 / 活动订单状态 |

冻结用户统一处理：

```text
冻结用户
├─ 无活动订单 → 禁止进入正常业务
└─ 有活动订单 → 允许进入 U04
                 ├─ 停止充电
                 └─ 完成结算
```

进入受限收尾流程后，充值、创建新订单、开始新业务等其他业务按钮均处于 Disabled 状态。

| 区域 | 元素 | 作用 | 数据来源 |
| --- | --- | --- | --- |

### U04 当前充电 / 订单处理页

| 区域 | 元素 | 作用 | 数据来源 |
| --- | --- | --- | --- |
| 订单摘要 | 站点、电桩、单价、订单状态 | 显示当前活动订单 | ORDER_ACTIVE_CHECK / 当前订单 |
| 充电数据 | 时长、电量、金额 | 展示服务端权威充电进度 | 服务端权威数据；刷新机制待 API 契约冻结 |
| 主操作 | 开始充电 | CREATED → CHARGING | ORDER_START |
| 主操作 | 取消预约 | CREATED → CANCELLED | ORDER_CANCEL |
| 主操作 | 停止充电 | CHARGING → PENDING_PAYMENT | ORDER_STOP |
| 结算区 | 应付金额、钱包余额、确认结算 | PENDING_PAYMENT 时完成扣款 | ORDER_SETTLE + 用户余额 |
| 提示区 | 余额不足 / 非法状态 / 未完成订单提示 | 处理异常并引导用户 | 服务端 code/message |

充电进度统一约束：

- 充电时长、电量、金额均以 `qt-server` 返回的权威数据为准；
- UI 不自行计算金额，不自行推导最终充电状态；
- U04 打开时立即请求一次；充电中的订单由客户端每 1 秒发送一次 `ORDER_ACTIVE_CHECK`；
- 页面离开 U04 或订单不再是 `CHARGING` 时停止轮询；
- 接口冻结前，UI 模块不得自行新增协议。

冻结用户如果已经存在活动订单：

- 允许在 U04 执行 `ORDER_STOP`；
- 允许在 U04 执行 `ORDER_SETTLE`；
- 禁止创建新订单、开始新的业务流程；
- 与收尾无关的业务按钮保持 Disabled。

Dashboard 电桩状态统计口径固定为：

```text
闲置 = AVAILABLE
在用 = CHARGING
故障 = FAULT
```

补充规则：

- `OFFLINE` 不计入“闲置”；
- `RESTARTING` 不计入“闲置”；
- `RESERVED` 不计入“闲置 / 在用 / 故障”三项核心统计；
- `RESERVED` 在 A03 充电桩管理表格中单独显示为“已预约”，Dashboard 首版不额外增加第四张核心状态卡片。

## 9. 接口联调检查

后端接口文档完成后，逐页核对：①页面显示的数据字段是否都能返回；②按钮操作是否有对应消息类型；③成功/失败是否返回 `code/message`；④状态枚举是否与 UI 文案一致；⑤充电页是否按约定调用 `ORDER_ACTIVE_CHECK`。

接口未完成前，可先使用 Mock 数据完成 UI 设计与 Qt 页面实现，但 UI 不得自行扩展 Socket 协议或自行计算充电金额。
