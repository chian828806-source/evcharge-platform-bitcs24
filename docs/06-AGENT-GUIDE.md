# Agent 协作规范

## 1. 使用范围

本项目允许使用 Agent 辅助：

- 编写代码
- 修改 Bug
- 补充测试
- 分析现有代码
- 完善文档
- 优化局部实现

但 Agent 不得自行：

- 修改系统总体架构
- 修改数据库公共结构
- 修改既有 API 契约
- 引入未经确认的新框架
- 大规模重构无关模块
- 删除现有有效功能

所有 Agent 修改均应遵循项目现有文档和目录结构。

## 2. 给 Agent 的必要上下文

所有成员给 Agent 的上下文必须包含：

1. 当前技术栈
2. 当前目录结构
3. 数据库结构
4. API 文档
5. 当前开发规范
6. 本次任务边界
7. 禁止修改的文件
8. 验收条件

必须明确告诉 Agent：

```text
不得自行更改既有数据库字段。
不得自行修改既有 API 路径。
不得自行引入新的框架或依赖。
不得重构无关模块。
不得删除现有功能。
必须遵循现有项目目录和命名规范。
```

## 3. 最小修改原则

Agent 修改代码优先采用最小修改原则。

例如任务是：

```text
增加手机号模糊查询
```

Agent 不得顺便：

```text
重构整个用户模块
修改 User Entity
更换数据库框架
修改统一返回结构
```

每次 Prompt 必须明确：

```text
只完成本次要求涉及的修改，不修改与本任务无关的已有功能。
```

## 4. 公共契约限制

数据库结构、API 接口及公共状态定义属于项目公共契约。

未经讨论不得自行修改：

- 数据库表名
- 数据库字段
- API URL
- HTTP Method
- 请求字段
- 响应字段
- 公共状态值

如确需修改，应先确认影响范围，再同步修改相关文档与代码。

## 5. API 修改约束

一旦接口进入联调阶段，任何人不得直接修改：

```text
URL
HTTP Method
请求字段
响应字段
状态含义
```

确需修改时：

```text
提出修改
↓
确认影响模块
↓
组长确认
↓
修改 API 文档
↓
修改代码
↓
通知相关成员
```

必须做到：

```text
先改文档，再改代码。
```

## 6. 数据库修改约束

数据库结构由：

```text
database/schema.sql
```

作为唯一正式版本。

任何表结构变动必须同步修改：

```text
schema.sql
docs/04-DATABASE.md
对应 Entity
相关 API
```

## 7. 后续 Linux 开发协作所需信息

后续进入编码阶段前，请提供以下内容：

- GitHub 仓库地址。
- 使用的默认分支和开发分支策略，例如 `main`、`develop`、`feature/*`。
- 虚拟机 IP、SSH 端口、登录用户名。
- SSH 登录方式：密码或密钥。
- 如果使用密钥，请确认密钥文件路径以及是否需要 passphrase。
- 虚拟机系统版本，例如 Ubuntu 22.04。
- 项目在虚拟机中的目标目录，例如 `/home/<user>/projects/evcharge-platform`。
- 虚拟机中已安装的软件版本：Git、JDK、Maven、MySQL、Qt、Node.js、Python。
- MySQL 连接信息：host、port、database、username、password，或说明暂时只用本地开发配置。
- 是否允许我在虚拟机中安装依赖、创建目录、运行服务和执行测试。
- 是否有需要禁止修改的文件或目录。
- 每次任务的验收条件。

在规范定义阶段，我只整理文档，不开展工程初始化、建库、安装依赖或编码。
