# Agent 协作规范

本文档定义团队使用 AI Agent 的输入上下文、允许范围、禁止事项和验收要求。

## 1. 基本原则

Agent 可以参与：

- 编写代码
- 修改 Bug
- 补充测试
- 分析现有代码
- 完善文档
- 优化局部实现

Agent 不具有自行修改项目架构和公共契约的权限。

公共契约包括：

- SRS 需求编号和需求含义
- Socket Message Type / 请求字段 / 响应字段
- API URL / Method / 请求字段 / 响应字段
- 数据库表和字段
- 公共状态枚举
- 设备协议消息格式
- 技术栈和依赖

## 2. Contract Read-First

任何 Agent 开始编码前，必须先阅读与任务相关的文档：

- `docs/00-SRS-V1.0.md`
- `docs/01-ARCHITECTURE.md`
- `docs/02-DEVELOPMENT-GUIDE.md`
- `docs/03-API.md`
- `docs/04-DATABASE.md`
- `docs/07-DEVICE-PROTOCOL.md`，如涉及设备
- 当前模块 README 或已有代码

不得在不了解现有契约的情况下直接生成代码。

## 3. 给 Agent 的必要上下文

每次任务至少提供：

1. 需求编号。
2. 当前技术栈。
3. 当前目录结构。
4. 涉及 Socket 消息或 REST API。
5. 涉及数据库表。
6. 涉及状态枚举。
7. 本次任务边界。
8. 禁止修改的文件或契约。
9. 验收条件。
10. 可运行或测试命令。

推荐 Prompt：

```text
本次任务对应 SRS: FR-C-007。
只实现钱包结算相关逻辑。
不得修改既有 Socket 消息类型或 API 路径。
不得修改数据库字段。
不得引入新框架。
不得重构无关模块。
完成后运行相关测试，并说明修改文件和验证结果。
```

## 4. 最小修改原则

Agent 应优先做完成任务所需的最小修改。

例如任务是：

```text
增加手机号模糊查询
```

Agent 不得顺便：

```text
重构整个用户模块
修改 User Entity
更换数据库框架
修改统一返回结构
```

## 5. 禁止事项

Agent 不得自行：

- 修改系统总体架构。
- 修改 SRS 已冻结需求。
- 修改数据库公共结构。
- 修改既有 Socket 业务消息或 API 契约。
- 修改公共状态枚举。
- 修改设备协议。
- 引入未经确认的新框架或依赖。
- 大规模重构无关模块。
- 删除现有有效功能。
- 绕过后端让客户端直接操作主数据库。
- 把敏感信息写入仓库。

## 6. 接口修改约束

一旦 Socket 业务消息或 REST API 进入联调阶段，任何 Agent 不得直接修改：

```text
Message Type
URL
HTTP Method
请求字段
响应字段
状态含义
错误码
权限规则
```

确需修改时：

```text
提出修改
↓
确认影响模块
↓
组长确认
↓
修改接口文档
↓
修改代码
↓
通知相关成员
```

必须做到：

```text
先改文档，再改代码。
```

## 7. 数据库修改约束

数据库结构由：

```text
database/schema.sql
```

作为唯一正式版本。

任何表结构变动必须同步修改：

- `database/schema.sql`
- `database/init_data.sql`
- `docs/04-DATABASE.md`
- 对应 Entity
- 相关接口文档

## 8. 设备协议修改约束

涉及设备通信时，Agent 必须先阅读：

```text
docs/07-DEVICE-PROTOCOL.md
```

不得自行增加或修改：

- 消息类型
- 状态枚举
- 通用字段
- ACK 规则
- 心跳间隔
- 离线判定

如需修改，必须先更新协议文档并经过组内确认。

## 9. 输出要求

Agent 完成任务后必须说明：

- 修改了哪些文件。
- 对应哪些需求编号。
- 是否修改公共契约。
- 执行了哪些测试或运行命令。
- 仍存在什么风险。

如果无法运行测试，必须说明原因。

## 10. Diff Review

提交前必须检查 diff：

- 是否只改了本任务相关文件。
- 是否误删文件。
- 是否改动敏感配置。
- 是否引入临时文件。
- 是否包含无关格式化。
- 是否包含调试输出。

## 11. Linux 虚拟机协作所需信息

进入编码阶段前，请提供：

- GitHub 仓库地址。
- 默认分支和开发分支策略，例如 `main`、`develop`、`feature/*`。
- 虚拟机 IP。
- SSH 端口。
- SSH 用户名。
- SSH 登录方式：密码或密钥。
- 如果使用密钥，请确认密钥文件路径以及是否需要 passphrase。
- 虚拟机系统版本，例如 Ubuntu 22.04。
- 项目在虚拟机中的目标目录，例如 `/home/<user>/projects/evcharge-platform`。
- 虚拟机中已安装的软件版本：Git、JDK、Maven、MySQL、Qt、Node.js、Python。
- MySQL 连接信息：host、port、database、username、password，或说明暂时只用本地开发配置。
- 腾讯地图 Key 的配置方式。
- 是否允许我在虚拟机中安装依赖、创建目录、运行服务和执行测试。
- 是否有需要禁止修改的文件或目录。
- 每次任务的验收条件。

在规范定义阶段，只整理文档，不开展工程初始化、建库、安装依赖或编码。
