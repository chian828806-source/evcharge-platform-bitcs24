# EVCharge Qt UI 总设计 V1.0

 Qt 用户端 + PC 服务与管理端 UI

## 1. 设计说明

设计依据：仓库 README.md、docs/00-SRS-V1.0.md、docs/03-API.md，以及老师原项目要求书。老师要求书用于确定必做功能，仓库最新版需求确定具体业务范围。

覆盖当前仓库中与 Qt 用户端、Qt 管理端 UI 直接相关的主要需求。Socket、业务规则、SQLite、多线程、Web、ML 等由对应模块实现。

## 2. 页面规划

| 端 | 主页面数 | 页面 |
| --- | --- | --- |
| Qt 用户端 | 6 | 手机号登录；首页/附近充电站；充电站详情；当前充电/订单处理；我的；地图导航 |
| PC 服务与管理端 | 5 | 管理员登录；运营 Dashboard；充电桩管理；充电站管理；用户管理 |

## 3. Qt 用户端 UI 总设计

用户端采用模拟手机端布局。主导航保留：首页 / 充电 / 我的。地图导航从充电站详情进入。

| 编号 | 页面 | 主要目的 | 关键跳转 |
| --- | --- | --- | --- |
| U01 | 手机号登录 | 手机号免密登录；不存在则自动注册 | 登录成功 → U02 |
| U02 | 首页 / 附近充电站 | 定位、展示附近站点与推荐 | 站点 → U03；充电 → U04；我的 → U05 |
| U03 | 充电站详情 | 查看站内电桩并选择可用桩 | 导航 → U06；选择电桩 → U04 |
| U04 | 当前充电 / 订单处理 | 覆盖预约、开始、充电、停止、结算 | 完成后 → U02 / U05 |
| U05 | 我的 | 用户资料、钱包、历史订单 | 首页 → U02；未完成订单 → U04 |
| U06 | 地图导航 | 腾讯地图路线规划 | 返回 → U03 |

### U02 首页 / 附近充电站

### U03 充电站详情页

| 区域 | 元素 | 作用 | 数据来源 |
| --- | --- | --- | --- |

### U04 当前充电 / 订单处理页

| 区域 | 元素 | 作用 | 数据来源 |
| --- | --- | --- | --- |
| 订单摘要 | 站点、电桩、单价、订单状态 | 显示当前活动订单 | ORDER_ACTIVE_CHECK / 当前订单 |
| 充电数据 | 时长、电量、金额 | 展示模拟充电过程 | 服务端实时/定时更新 |
| 主操作 | 开始充电 | CREATED → CHARGING | ORDER_START |
| 主操作 | 取消预约 | CREATED → CANCELLED | ORDER_CANCEL |
| 主操作 | 停止充电 | CHARGING → PENDING_PAYMENT | ORDER_STOP |
| 结算区 | 应付金额、钱包余额、确认结算 | PENDING_PAYMENT 时完成扣款 | ORDER_SETTLE + 用户余额 |
| 提示区 | 余额不足 / 非法状态 / 未完成订单提示 | 处理异常并引导用户 | 服务端 code/message |

### U05 “我的”页

| 区域 | 元素 | 作用 | 数据来源 |
| --- | --- | --- | --- |
| 用户卡片 | 头像、昵称、手机号 | 显示当前用户资料 | USER_PROFILE_GET |

| 账户区 | 退出登录 | 清空本地会话并回到登录页 | 本地 session |

### U06 地图导航页

| 区域 | 元素 | 作用 | 数据来源 |

## 8. 接口联调检查

后端接口文档完成后，逐页核对：①页面显示的数据字段是否都能返回；②按钮操作是否有对应消息类型；③成功/失败是否返回 code/message；④状态枚举是否与 UI 文案一致。接口未完成前，可先使用 Mock 数据完成 UI 设计与 Qt 页面实现。
