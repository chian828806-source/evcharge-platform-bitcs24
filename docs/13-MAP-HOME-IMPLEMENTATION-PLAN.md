# 用户端地图首页实施计划

状态：拟实施，尚未进入接口和数据库变更阶段
适用范围：`qt-user/` 地图首页、`qt-server/` 站点查询能力
最后更新：2026-09-09

## 1. 目标

将“附近充电站”升级为首页的核心体验：上半部分展示可交互腾讯地图，地图上展示当前位置和附近充电站；下半部分展示站点列表。用户可展开列表，以列表浏览为主，也可在地图上点击站点直接查看详情或发起导航。

本功能不改变电桩预约、订单、计费与结算规则。

## 2. 首版交互范围

```text
┌──────────────────────────────┐
│ 搜索地址 / 预设定位 / 筛选    │
├──────────────────────────────┤
│ 腾讯交互地图                  │
│  蓝色圆点：当前位置            │
│  绿色图钉：可用站点            │
│  灰色图钉：无空闲桩的正常站点  │
├───────────────⌃──────────────┤
│ 附近站点抽屉                  │
│  站点卡片、距离、价格、空闲桩  │
└──────────────────────────────┘
```

- 初始状态：地图与列表各约占半屏；
- 点击抽屉顶部把手：在“半屏列表”和“全屏列表”之间切换；
- 后续增强：支持鼠标或触摸拖动把手；首版不以复杂手势作为验收前提；
- 点击地图站点图钉：高亮同一站点卡片，并显示名称、综合电价、空闲桩与“查看详情”；
- 点击站点卡片：地图居中至该站点；点击“导航到这里”进入既有路线导航页；
- 地址搜索成功后：更新蓝色当前位置、地图中心、站点距离和列表排序；
- 地址搜索失败后：保留上一次成功的位置和列表，并明确显示失败原因。

## 3. 位置口径

当前项目没有接入电脑或手机的 GPS 定位，因此首版的“当前位置”定义为：

1. 默认位置：项目提供的演示位置；
2. 用户选择预设位置或输入地址后，由 `MAP_GEOCODE` 解析出的坐标；
3. UI 展示为“模拟当前位置”或“当前搜索位置”，不宣称读取真实 GPS。

若以后接入真实定位，需要单独处理平台权限、定位失败与用户隐私授权；这不纳入本次实施。

## 4. 现有能力与新增边界

| 能力 | 当前情况 | 首页实现方式 |
| --- | --- | --- |
| 地址转坐标 | 已有 `MAP_GEOCODE` | 复用，不新增接口 |
| 附近站点查询 | 已有 `STATION_LIST_NEARBY` | 复用，返回的经纬度用于画图钉 |
| 路线规划 | 已有 `MAP_ROUTE_PLAN` | 复用既有导航页 |
| 交互地图 | 已有 `MapNavigationPage` 和腾讯 JavaScript API GL | 抽出可复用的站点地图组件，不复制整段 HTML |
| 真实 GPS | 未实现 | 本期不做 |

地图脚本的 `TENCENT_MAP_JS_KEY` 仍由 `qt-user` 的运行环境读取；服务端 WebService Key/SK 仍只放在服务端环境。任何 Key、SK 都不得写入源码、`.pro` 文件、文档示例中的真实值或 Git 仓库。

## 5. 推荐代码结构

建议新增一个专门显示站点的组件，而不是把站点标记逻辑继续堆进 `UserWindow`：

```text
qt-user/
├─ map/
│  ├─ mapnavigationpage.*       # 已有：路线导航
│  └─ stationmapwidget.*        # 新增：首页地图、当前位置、站点图钉
└─ ui/
   └─ userwindow.*              # 组装首页、列表抽屉和信号联动
```

`StationMapWidget` 负责生成地图页面、画当前位置和站点图钉、接收图钉点击事件；`UserWindow` 只负责请求服务端、维护当前坐标和选中站点、刷新站点卡片。这样路线导航与首页找桩不会互相污染。

## 6. 实施步骤

### 阶段 A：先固定 UI 状态

1. 将当前“附近充电站”页面调整为地图区 + 列表抽屉；
2. 实现半屏/全屏列表的点击切换；
3. 保留现有地址搜索、预设定位、站点详情和导航按钮；
4. 无地图 Key、网络失败时显示占位提示，但站点列表仍可工作。

### 阶段 B：接入地图站点标记

1. 从 `m_nearbyStations` 读取 `stationId`、`name`、`longitude`、`latitude`、`availablePileCount`；
2. 以当前位置和全部正常站点创建标记；
3. 标记点击后传回 `stationId`，高亮相应卡片；
4. 卡片点击后调用地图居中与弹出信息窗。

### 阶段 C：刷新与联调

1. `MAP_GEOCODE` 成功后重新请求 `STATION_LIST_NEARBY`；
2. 收到站点结果后同时更新列表和地图，避免两者数据不一致；
3. 检查无 Key、无网络、空站点、无空闲桩、地址解析失败五种状态；
4. 验证地图缩放、拖动仍由 `QWebEngineView` 正常处理。

## 7. 验收清单

- 地址搜索成功后，蓝色当前位置和站点距离发生变化；
- 地图图钉数量与列表站点数量一致；
- 点击图钉和点击卡片能选中同一站点；
- 地图不可用时，站点列表、详情和预约流程不被阻断；
- 用户端不包含 WebService Key/SK；
- 首页不直接读取 SQLite。

## 8. 待确认项

1. 首版是否只展示 `NORMAL` 站点（建议：是，与现有用户查询一致）；
2. 无空闲桩的站点是隐藏、灰色展示还是保留绿色展示（建议：灰色保留，方便用户了解站点位置）；
3. 是否在首页加入“快充/慢充、仅空闲、距离排序”等筛选（建议：地图首版完成后再加）；
4. 是否要接入真实 GPS（建议：本项目演示阶段先不做）。
